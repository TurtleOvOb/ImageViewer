# 项目介绍

ImageViewer 是一个用 Qt Widgets 写的本地图片查看器兼简易编辑器。选择一个文件夹批量加载图片，用缩略图网格浏览，对单张图做灰度、反转、镜像、对比度、亮度和旋转，处理结果可以另存到本地。

项目定位是练手：把事件驱动、信号槽、资源生命周期、界面与数据分离这几件事，在一个能真正跑起来的程序里完整走一遍。所以代码里保留了一些"当时为什么这么改"的注释，文档末尾也记了已知的不足。

# 功能特性

## 图片浏览

- 选择文件夹批量加载，支持 jpg / jpeg / png / bmp / webp / svg（后缀按精确匹配， 也支持JPG、PNG ）
- 缩略图网格显示，点击切换当前图片
- 上一张 / 下一张按钮
- 移除选中图片
- 显示区支持滚轮缩放、按住拖动平移，切换图片时自动适应窗口

## 图片编辑

- 颜色反转、灰度化、镜像
- 对比度、亮度
- 旋转
- 还原：当前图片的参数一键复位

## 结果输出

- 另存为：把渲染后的结果保存成 png 或 jpg
- 右键菜单：把当前渲染结果复制到剪贴板


# 环境依赖

- Qt 6.9.3（安装时选择 msvc2022_64 构建）
- CMake 3.16 以上，生成器使用 Ninja
- MSVC 2022，需要支持 C++17
- 图片格式插件：WebP、TIFF、TGA、ICNS、WBMP 这几个格式由 Qt 的 **Qt Image Formats** 附加模块提供，需要在 Qt 维护工具里勾选安装，否则后缀虽然被放行，加载时仍然会失败
- 不支持的格式：AVIF。Qt 官方不提供解码，需要额外的第三方插件

# 使用说明

## 编译

在 Visual Studio 的开发者命令行里执行：

```
cmake --preset Debug-x64
cmake --build out/build/debug
```

Release 构建把预设换成 Release-x64，输出目录是 out/build/release。

## 运行

保证 Qt 的 bin 目录在 PATH 中，或者把输出目录交给 windeployqt 处理依赖，然后直接运行 ImageViewer.exe。

构建配置注意事项：

- `Q_ASSERT` 只在 Debug 构建里生效，Release 下会被裁掉。同一段代码 Debug 崩溃而 Release 不崩溃，通常就是这个原因。
- `qDebug` 输出的 `[文件:行号]` 前缀也只有 Debug 下才有，Release 下会显示成 `[unknown:0]`。

## 操作说明

1. 点"选择文件夹"，程序会把该目录下的图片全部加载进来，缩略图排在右侧网格中；重复选择新文件夹时，之前的缩略图和数据会被清空。
2. 点击任意缩略图切换到那张图，也可以用"上一张""下一张"顺序浏览。
3. 左侧的复选框和滑块对当前图片生效，效果即时显示。
4. "还原"把当前图片的所有参数复位。
5. "另存为"把当前渲染结果存成 png 或 jpg。
6. 在图片上点右键可以复制当前渲染结果到剪贴板。
7. "移除"把当前图片从列表和数据中删掉。

## 单元测试

测试只覆盖数据层 imageManager，不涉及界面。

```
cmake --build out/build/debug
ctest --test-dir out/build/debug --output-on-failure
```

想单独运行并查看每个用例的名字和耗时，直接执行 out/build/debug/test2.exe；加 `-functions` 可以列出它识别出的测试函数，加 `-v1` 会逐个打印执行过程。

目前有 10 个用例：加图后能按 id 取回原图、删除后其余图片仍可用、单张图时上一张与下一张都返回 -1、跨图参数互不污染、旋转 90 度后像素位置正确、颜色反转的通道值、灰度化后三通道相等、镜像后左右互换、非法 id 返回空图且不崩、超范围参数被截断到合法区间。

测试用图由 QTemporaryDir 现场生成 8x8 纯色 PNG，不依赖任何真实照片，可以反复运行。

# 代码组织架构

| 类 | 位置 | 职责 |
| --- | --- | --- |
| imageManager | manager/ | 单例。持有全部图片及其参数，负责分配 id、按 id 查找、设置参数、渲染 |
| thumbnailManager | manager/ | 只负责创建缩略图控件 |
| MyLabel | Widgets/ | 缩略图控件。不保存 id，被点击时只发一个无参信号 |
| MyGraphicsView | Widgets/ | 显示区。整个生命周期只创建一次，切图时只替换 pixmap |
| ImageViewer | main/ | 主窗口。把上面几者串起来，负责控件状态与数据的同步 |

id、下标与 curId

- id 是身份的标识，创建时分配、单调递增，删除之后不复用。它只回答"这是哪张图"。
- 下标是图片在数组中的位置。删除会让后面的元素前移，所以同一个 id 对应的下标随时可能变。
- `indexOf(id)` 负责把身份翻译成位置，找不到返回 -1。调用方拿到 -1 必须先判负，直接拿它当数组下标就会越界。
- curId 是当前选中的图片。另外还有一个 curIndex，只用于切换上一张/下一张。

## 渲染管线

`render(id)` 不在原图上叠加修改，而是每次从原图重新计算一遍，顺序固定：

```
反转 → 灰度 → 镜像 → 对比度与亮度 → 旋转
```

对比度和亮度共用一个 256 项的查找表，先把整张映射关系算好再套到像素上；旋转用 QTransform 绕图片中心进行，采用平滑采样。参数全部为默认值时，渲染结果与原图逐像素相同。

# 已知限制

按影响大小排列：

1. 参数同步依赖控件的信号，比较脆弱。切图时先显示原图，靠回填复选框和滑块触发重算；如果目标图片的参数与当前控件值恰好相同，信号不会发出，需要手动补一次信号，否则画面不更新。
2. `get_params` 和若干 `set_xxx` 没有校验 id，传入不存在的 id 会访问数组的 -1 位置，Debug 下触发断言，Release 下是未定义行为。`render` 和 `get_ImageById` 已经做了判负处理，其余入口尚未补齐。
3. 原图和缩略图全部常驻内存，图片数量多时内存占用大。
4. 拖动对比度或亮度滑块时，每个 valueChanged 都会重算整张图，大图上会明显卡顿。
5. 没有撤回功能。原本考虑过用 QUndoCommand 实现，评估实现成本后没有做（其实是懒得做）。
6. 后缀过滤是写死的白名单，与运行时实际可解码的格式并不等价。例如 Qt 本身还能读 gif、ico、tiff，但白名单没有放行；AVIF 则相反，后缀不被识别，即使文件本身没问题也会被跳过。
